# 抓包与报文定位速查

> 面向"服务在跑、但数据不对"的排查场景：怎么抓、怎么滤、怎么把报文拿出来看。
> 环境：CentOS 7 上的转发类服务 + Windows 上的业务服务。

---

## 一、抓包前先想清楚三件事

1. **抓哪条链路**？（本机转发链 / 与对端的链路 / 某一台主机的进出）
2. **按什么条件过滤**？（IP + 端口是最小必要集）
3. **要的是统计还是报文本身**？（看"通不通"和看"内容对不对"是两件事）

**顺序建议**：先 `-c` 抓几条确认有流量 → 再加过滤条件 → 最后决定是否输出为十六进制看内容。

---

## 二、tshark 常用式

### 2.1 只看"有没有包、转发成不成功"

```bash
# 抓任意网卡上 目的IP:端口 的包，只取 10 条
tshark -i any -Y "ip.dst == 192.0.2.148 && tcp.dstport == 8055" -c 10 -T fields -e data

# 抓与某主机某端口的往来
tshark -i any -f "host 203.0.113.143 and port 7865" -c 10
```

- `-i any`：所有网卡；也可指定 `-i eth0`
- `-f`：**BPF 捕获过滤器**（在内核层就过滤，效率高，语法是 `host` / `port`）
- `-Y`：**显示过滤器**（抓完再滤，语法是 `ip.dst ==`，更灵活）
- `-T fields -e data`：**只输出载荷字段** —— 这是看"内容"的关键
- `-c N`：抓 N 条后自动停止（**不加会一直挂着**）

### 2.2 把报文取出成十六进制，直接丢给解析工具

```bash
tshark -i any -f "host 203.0.113.143 and port 7865" -c 10 -T fields -e data
```

输出的十六进制串可直接喂给协议解析脚本（如 808 / 809 报文解码器）。

### 2.3 常用判读

| 现象 | 指向 |
|---|---|
| 目标口一个包都没有 | 流量根本没到本机（路由 / NAT / 防火墙上游） |
| 有请求无应答 | 对端未处理，或应答被拦在回程路径 |
| 请求与应答都有，但业务仍失败 | 报文内容 / 参数问题，不是链路问题 |

> ⚠️ **抓包要按链路分别看**。同一台机器上可能同时跑着多条转发链（如接入网关与平台间转发），**抓 A 链路的包看不到 B 链路的报文** —— 用端口和 IP 把链路区分开。

## 三、原始报文还能从哪拿

抓包不是唯一途径，很多时候**日志里有现成的**：

| 途径 | 说明 |
|---|---|
| **容器 / 程序自身日志** | 若程序把报文写进日志目录，直接读日志即可（**注意用支持 UTF-8 的终端打开**，否则中文乱码） |
| **上游平台日志** | 与上游平台**直连**的链路，原始报文通常在上游侧日志里 |
| **经过本机转发的链路** | 本机若无落盘日志，只能靠抓包 |

> ⚠️ 日志保留期是硬约束：流量类日志往往**只保留几天**。事后排查"上周发生的问题"时，**原始报文很可能已经滚掉了** —— 这时只能改用分布特征（同期同类数据的对比）来归因，而不是靠单条报文定案。

**日志轮转陷阱**：用 `tail -1` 的文件修改时间判断"服务什么时候停的"容易被 `logrotate` 骗到（那是轮转时间，不是业务停止时间）。**要按内容里的时间戳定位。**

## 四、网络连通性排查

```bash
## Linux
ss -tlnp | grep :<端口>          # 端口是否在监听（先看这个，别急着开防火墙）
telnet <ip> <端口>               # 端口是否可达
traceroute <ip>                  # 路径在哪一跳断掉
ping <ip>                        # 仅表示 ICMP 可达，不代表端口通

## Windows
netstat -ano | findstr ESTABLISHED     # 实时 TCP 连接
netstat -ano | findstr ":<端口>"        # 某端口状态
telnet <ip> <端口>
Test-NetConnection <host> -Port <端口>
```

**顺序**（缺一不可）：

```
① 进程在不在 → ② 端口在不在监听 → ③ 本机防火墙 → ④ 云安全组 → ⑤ 路由/对端
```

**两个高频误判**：

- **`ping` 不通不代表服务不通** —— 很多生产机禁 ICMP，但业务端口正常。
- **`ping` / `telnet` / `ssh` 三者全不通时，别只往网络拦截上想** —— **主机根本没启动**（RAID 未组装、无启动设备）也是这个现象。这时应去带外管理（iDRAC / IPMI）或机房现场看 POST 画面。

## 五、防火墙规则维护

```bash
service iptables save                          # 保存（CentOS 7 习惯路径）
iptables-save > /etc/sysconfig/iptables        # 等价的手工写法
iptables -t nat -L -n -v --line-numbers        # 带计数看规则命中情况
```

**Windows 侧放行端口**：

```cmd
netsh advfirewall firewall add rule name="<规则名>" dir=in action=allow protocol=TCP localport=8080,8081
```

> 🔴 **绝对不要在生产上执行 `iptables -F`**。远程操作时清空规则 = 把自己关在门外，且中断所有转发业务。真要重建规则，先 `iptables-save > 备份文件`。

> 🔴 **规则要幂等**：定时任务重复 `iptables -A` 会不断追加重复规则。用 **先删后加** 或 **`-C` 检查存在性** 的写法。
> 修改端口时，**先删旧规则再加新规则**（先加后删会出现端口冲突的中间态）。

## 六、查找与文本处理

```bash
locate -i -n 10 -e <文件名>
#   -n 限制返回条数 | -e 只显示磁盘上真实存在的文件 | -i 忽略大小写
#   ⚠️ 刚创建/刚删除的文件查不到 → 先 updatedb 更新索引

grep -vE '^\s*(#|$)' <文件>     # 去掉注释行和空行（读配置文件的实用式）

grep -n "关键字" <文件>          # 带行号

# 按路径找文件（比 find 快，但依赖索引）
updatedb && locate <文件名>
```

## 七、Windows 侧的别名陷阱（务必过一遍）

**PowerShell 里多个命令名被劫持为别名**，直接用在服务 / 网络操作上会**静默返回错误结果**：

| 别名 | 实际指向 | 危险 |
|---|---|---|
| **`sc`** | `Set-Content` | ⚠️ **查服务返回空而不报错** |
| `curl` | `Invoke-WebRequest` | 参数完全不同 |
| `rm` | `Remove-Item` | 参数不同 |
| `kill` / `sleep` / `ls` / `cat` / `sort` / `select` | 各类 cmdlet | 参数语义有差异 |

**规则**：给 Windows 的命令，先按目标 shell（PowerShell 还是 CMD）解析一遍，确认不会被别名吞掉；不确定时**优先用原生 cmdlet 或显式带 `.exe`**。

### 服务查询（老机 / 生产机默认给 CMD）

```cmd
sc query <服务名>          :: 状态
sc qc <服务名>             :: 启动类型、可执行路径、依赖
sc queryex <服务名>        :: 带 PID
sc enumdepend <服务名>     :: 依赖关系
net helpmsg <错误码>       :: 中文错误含义（1053 = 服务没有及时响应启动或控制请求）
```

PowerShell 等价（**PS 3.0+** 才有 `Get-CimInstance`）：

```powershell
Get-Service <服务名> | Select-Object Status,StartType
Get-CimInstance Win32_Service -Filter "Name='<服务名>'" | Select-Object State,StartMode,PathName
sc.exe qc <服务名>          # 显式 .exe 绕开别名
```

> **版本识别**：`Get-CimInstance` / `Get-WinEvent -FilterHashtable` 是 **PS 3.0+** 才有的。**PS 2.0（对应 Windows Server 2008 R2 / Windows 7 级别）没有这两个**，老机上一律改用 `Get-WmiObject`、`Get-EventLog`、`sc.exe`。识别信号：版本横幅写「版权所有 (C) 2009」= PS 2.0。

## 八、CMD 的三个坑

1. **`.bat` 文件里绝不能有中文** —— cmd 按 GBK 解析 UTF-8 会整行炸裂，后续命令全部不执行。批处理一律纯 ASCII。
2. **`for` 变量符**：命令行用 `%s`，写成 `.bat` 必须是 **`%%s`**（否则报"此时不应有 s"）。
3. **`state=` 后必须有空格**：`sc query state= all | findstr ...`。

> ⚠️ **多条命令不要一次粘进 CMD** —— 交互式粘贴时换行可能丢失，两条命令会被拼成一条（服务名被拼接 → 误报"指定的服务未安装"）。**要么一行一行贴，要么直接给 `.bat`。**
