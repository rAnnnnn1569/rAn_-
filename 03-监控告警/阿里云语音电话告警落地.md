# 严重/灾难告警 —— 语音电话通知落地（阿里云 VMS）

> 适用场景：Zabbix 触发「严重 / 灾难」级别告警时，自动给值班手机**打电话语音播报**，确保不漏看。
> 设计原则：**电话只做「叫醒」**（念出"哪台主机 + 什么级别"），详细内容由已配好的飞书红卡 + 邮件承载，避免 TTS 念 IP / 长文本翻车。
> 与 [`三级告警分流设计.md`](./三级告警分流设计.md) 的关系：那份讲**为什么这样分级**（设计层），本文讲**具体怎么接**（实现层）。

---

## 一、计费（先说清楚：不是免费）

走**公共模式**最省钱（无需购买号码、无月租）：

| 项目 | 说明 |
|---|---|
| 语音通知（公共模式）后付费 | **¥0.11 / 分钟**，不足 1 分钟按 1 分钟计 |
| 一条严重告警电话 | 约 20~40 秒 → 记 1 分钟 ≈ **¥0.11 / 通** |
| 建议触发范围 | 仅「严重 / 灾难」，一月十几通 ≈ 一两元 |

> 升级选项：若要**固定外显号码**（接听率更高，公共模式是随机本地号易被当骚扰），改**专属号码模式**：号码月租 ¥35/个/月 + 通话费（阶梯 ¥0.11→¥0.088/分钟）。本文默认公共模式。

## 二、前置条件

1. 阿里云账号已**企业实名**且有余额。
2. 拿到 RAM 子账号的 **AccessKeyId / AccessKeySecret**（仅授权语音服务 `dyvms:*`）。
3. **跑告警脚本的机器能出网访问 `dyvmsapi.aliyuncs.com:443`**（详见第八节，与服务器是否阿里云无关）。

---

## 三、控制台准备（4 步）

1. **开通语音服务**
   控制台搜「语音服务」→ 开通（账户已实名 + 有余额，直接过）。

2. **提交资质（公共模式）**
   语音服务 → 资质话术管理 → 新增资质，场景选「系统告警 / 运维通知」，填营业执照 + 话术说明。审核通常 2 小时内自动过。

3. **建语音模板（公共模式）**
   语音模板管理 → 新增「文本转语音（公共模式）」模板，内容示例：
   > 告警，主机 `${host}` 发生 `${severity}` 级告警，请立即处理
   - 变量：`host`、`severity`。
   - ⚠️ **模板禁止出现 IP / 链接**（阿里云规则，IP 的 `.` 要改成 `_`）。所以主机名尽量用可读名而非裸 IP；若 Zabbix 主机名就是 IP，建议用主机的「可见名称」填可读名。
   - 审核通过后拿到 **模板 ID，形如 `TTS_xxxxxxxx`**。

4. **建 RAM 子账号拿 Key**
   访问控制 → 创建用户 → 仅授权 `AliyunDyvmsFullAccess`（或自定义仅 `dyvms:*`）→ 创建 AccessKey。

## 四、Zabbix 服务器侧部署

在 **Zabbix server 所在机器**（需 Python3 + 能出网）执行：

```bash
pip3 install aliyun-python-sdk-core aliyun-python-sdk-dyvmsapi
```

把下面脚本放到 Zabbix 的 `AlertScriptsPath`（查 `zabbix_server.conf` 的 `AlertScriptsPath`，常见 Linux `/usr/lib/zabbix/alertscripts/`；Windows 如 `C:\zabbix\alertscripts\`），命名 `aliyun_voice_alert.py`，并 `chmod +x`（Linux）。

> 完整脚本见附录一。把其中的 `ACCESS_KEY_ID`、`ACCESS_KEY_SECRET`、`TTS_CODE` 换成实际值；公共模式 `CALLED_SHOW_NUMBER` 留空。

本地自测（确保链路通）：

```bash
python3 aliyun_voice_alert.py 138xxxxxxxx '{ "host":"测试主机","severity":"严重" }'
```

手机应收到语音播报；返回 JSON 含 `CallId` 即成功。

> ⚠️ 凭据管理底线：AccessKey 属高敏感凭据，**不要硬编码进脚本后提交到任何代码仓库**。生产上建议放进受限权限的配置文件或环境变量，并在文件系统层面收紧读权限。

## 五、Zabbix 配置（3 处）

### 1）报警媒介类型

- 名称：`AliyunVoice`
- 类型：**脚本**
- 脚本名称：`aliyun_voice_alert.py`
- 脚本参数（支持宏）：
  1. `{ALERT.SENDTO}`
  2. `{ "host":"{HOST.NAME}", "severity":"{TRIGGER.SEVERITY}" }`

### 2）用户媒介 + 严重度过滤

- 在值班人员（如 `Admin` 或专门 on-call 用户）的「报警媒介」里添加 `AliyunVoice`，**发送到 = 手机号**。
- 该媒介的**严重度只勾「严重」和「灾难」**（其余取消）→ 普通告警绝不触发电话。

### 3）动作

- 名称：`严重灾难-电话告警`
- 条件：`触发器严重度 >= 严重` + `触发器值 = 问题` + （建议）`未处于维护期`
- 操作：发送到「用户」→ 仅选择 `AliyunVoice` 媒介（消息模板无所谓，脚本用第 2 参数）。

## 六、防骚扰 & 可靠性（必看）

- **去重 / 避免轰炸**：动作里把「步骤持续时间」设大（如 30 分钟），或勾选「问题确认后暂停」——被叫人接电话后在 Zabbix 确认，后续不再重拨。
- **维护期**：服务器维护时加维护，电话自动不响。
- **恢复不打电话**：默认只有 PROBLEM 事件触发，OK/恢复不会拨号（细节走飞书/邮件）。
- **接听率**：公共模式外显随机本地号，可能被当骚扰。若屡次不接，升级专属号码模式（固定外显号，¥35/月）。
- **出网**：确认 Zabbix server 能访问 `dyvmsapi.aliyuncs.com`（企业防火墙/安全组放行 443）。

## 八、FAQ：Zabbix 不在阿里云上，能用吗？

**能，完全不受限。** 阿里云语音服务（VMS）是对公网开放的 API，按 AccessKey 鉴权，**调用方在哪台机器都行**：

- Zabbix 只是发一个 HTTPS 请求（带 AccessKey）给 `dyvmsapi.aliyuncs.com`，说"给某号播这条 TTS"。
- 真正响铃的是**阿里云用号码池打给值班手机**，接收方是正常移动网络，与 Zabbix 服务器物理位置无关。
- 唯一硬性前提：**跑脚本的机器能出网访问 `dyvmsapi.aliyuncs.com:443`**。

连通性自检（在 Zabbix server 上）：

```bash
# Linux
curl -sS -o /dev/null -w "%{http_code}\n" https://dyvmsapi.aliyuncs.com
# 返回任何 HTTP 状态码（含 400/404）都说明网络通；超时/连不上 = 出网被拦

# Windows (PowerShell)
Test-NetConnection dyvmsapi.aliyuncs.com -Port 443
```

- **能通** → 直接按上文部署，零改动。
- **不通**（机房出网受限 / 纯内网）→ 二选一：
  1. 防火墙 / 安全组**放行到 `dyvmsapi.aliyuncs.com` 的 443 出站**（推荐）；
  2. 把告警脚本放到一台**能上网的机器**上执行（如带公网 IP 的跳板机），Zabbix 通过外部脚本 / `zabbix_get` / SSH 远程触发。

## 附录一：告警脚本 `aliyun_voice_alert.py`

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
import os
import sys
from aliyunsdkcore.client import AcsClient
from aliyunsdkcore.acs_exception.exceptions import ClientException, ServerException
from aliyunsdkdyvmsapi.request.v20170525.SingleCallByTtsRequest import SingleCallByTtsRequest

# 优先从环境变量读取，避免凭据硬编码进源码
ACCESS_KEY_ID = os.environ.get("ALIYUN_AK", "")
ACCESS_KEY_SECRET = os.environ.get("ALIYUN_SK", "")
TTS_CODE = os.environ.get("ALIYUN_TTS_CODE", "TTS_xxxxxxxx")   # 控制台拿到的公共模式模板ID
REGION = "cn-hangzhou"
# 专属号码模式才需要下面这行，公共模式留空
CALLED_SHOW_NUMBER = ""        # 例: "0571xxxxxxxx"


def main():
    if len(sys.argv) < 3:
        print("usage: aliyun_voice_alert.py <phone> <tts_param_json>")
        sys.exit(1)
    if not ACCESS_KEY_ID or not ACCESS_KEY_SECRET:
        print("missing ALIYUN_AK / ALIYUN_SK")
        sys.exit(3)
    phone, tts_param = sys.argv[1], sys.argv[2]
    client = AcsClient(ACCESS_KEY_ID, ACCESS_KEY_SECRET, REGION)
    req = SingleCallByTtsRequest()
    req.set_accept_format('json')
    req.set_CalledNumber(phone)
    req.set_TtsCode(TTS_CODE)
    req.set_TtsParam(tts_param)
    if CALLED_SHOW_NUMBER:
        req.set_CalledShowNumber(CALLED_SHOW_NUMBER)
    try:
        resp = client.do_action_with_exception(req)
        print(str(resp, encoding='utf-8'))
    except (ClientException, ServerException) as e:
        print("Aliyun voice alert failed: %s" % e)
        sys.exit(2)


if __name__ == "__main__":
    main()
```

> 说明：Zabbix 以服务方式调起脚本时，环境变量通常不会自动继承。若服务侧拿不到 `ALIYUN_AK/SK`，改用受限权限的配置文件读取，**不要退回硬编码**。
