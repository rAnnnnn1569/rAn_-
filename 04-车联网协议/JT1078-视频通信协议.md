# 《JT/T 1078—2016 道路运输车辆卫星定位系统 视频通信协议》重点总结

> 文档性质：交通运输部行业标准（JT/T），**2016-10-21 发布、2017-01-01 实施**，正式版（非征求意见稿）。
> 归口：交通运输信息通信及导航标准化技术委员会。
> 起草：中国交通通信信息中心、北京国交信通 等（含多家车载视频终端厂商）。
> 适用范围：道路运输卫星定位系统**车载视频终端与企业视频监控平台间**传输音视频数据，以及**不同视频平台之间**交换和共享音视频资源。
> 定位：1078 是**视频通信协议**，建立在 808（终端↔平台信令）与 809（平台↔平台交换）之上——**1076 管"视频终端怎么做"（技术要求），1078 管"视频怎么传"（通信协议）**。

---

## 一、文档定位与上下游关系（概念）

- **1078 = 视频通信协议**，规定三层通信：
  1. 视频终端 ↔ 视频平台（基于 JT/T 808—2011 扩展）
  2. 音视频流服务器 ↔ 客户端播放软件（RTP 码流 + URL 拉流）
  3. 视频平台 ↔ 视频平台（基于 JT/T 809—2011 扩展，政府/企业监管共享）
- 配套标准：
  - 终端通讯协议：`JT/T 808—2011`（1078 的信令/消息组成/分包/加密全部沿用）
  - 平台数据交换：`JT/T 809—2011`（平台间通信基础与链路复用）
  - 视频终端技术要求：`JT/T 1076—2016`（逻辑通道号、终端能力定义）
  - 编码规则：`JT/T 415—2006`（车牌颜色等）
  - 流媒体：`IETF RFC 3550`（RTP）、`RFC 2854`（URL/MIME 编码）
- 与其他报警体系的区别：**1078 的视频报警类型编码是 `0x01xx` 体系，与地方主动安全补充规范的视频报警码 `0x02xx`、部省智能监控报警 `0xDxxx` 是不同编号空间**，对接时不要混用（详见第七节）。

---

## 二、核心概念与术语

| 术语 | 概念含义 |
|---|---|
| 码率 code rate | 单位时间传输数据位数，常用 kbps |
| 帧率 frame rate | 每秒更新帧数，FPS |
| 主码流 / 子码流 | 同一路视频的两路码流（主码流高清存储/实时，子码流低带宽预览） |
| 逻辑通道号 | 视频终端对音视频通道的逻辑编号，按 JT/T 1076—2016 表 2 |
| 物理通道号 | 终端实际硬件通道，从 1 开始；与逻辑通道通过"通道列表"映射 |
| 时效口令 AUTHORIZE_CODE | 企业平台生成、用于政府平台跨域访问验证的 64 位 ASCII 口令，每 24h 更新 |
| RTP | 实时传输协议（RFC 3550），1078 音视频流的实际承载方式 |

缩略语：AAC / MPEG / RTP / TCP / UDP / URL / UTF-8 / FTP。

## 三、协议总体架构（三层，概念图）

```
[车载视频终端] ──808扩展信令 + RTP码流──> [企业视频监控平台]
                                              │  ▲
                              809扩展(主/从链路)│  │ 时效口令/跨域验证
                                              ▼  │
                                    [政府视频监管平台]（归属地 / 上级 / 跨域）
                                              │
                               URL拉流 ──────> [客户端播放软件] ──RTP── [音视频流服务器]
```
- **信令**走 808/809 链路（文本指令，消息 ID 体系）；**音视频码流**走独立 RTP 链路（UDP 或 TCP）。
- 实时音视频传输**新建独立链路**，不复用普通定位/告警报文链路。

## 四、视频终端 ↔ 视频平台协议（概念）

### 4.1 协议基础
- 通信方式、数据类型、传输规则、消息组成 → 按 **JT/T 808—2011 第 4 章**。
- 信令报文连接/消息处理/加密机制 → 按 808 第 5/6 章。
- **报文两类**：
  - 信令数据报文：指令与应答，走 808 链路，分包需逐包应答。
  - 码流数据报文：音视频/透传数据，RTP 封装，新建链路。

### 4.2 继承与扩展（概念）
- **继承** JT/T 808—2011 除 `0x8804`（录音开始）外的指令。
- 808 中多媒体事件/数据上传等 5 条指令（0x0800/0x0801/0x8802/0x0802/0x8803）在本标准中**多媒体类型只含"图片"**，音视频数据改按 1078 的实时/历史通道传输。

### 4.3 参数设置（终端音视频能力配置）
- 扩展 808 的 `0x8103` 参数设置，新增音视频参数：
  - 实时流 / 存储流的**分辨率**（QCIF/CIF/WCIF/D1/WD1/720P/1080P/自定义）、**编码格式**（CBR 固定 / VBR 可变 / ABR 平均码率）、**关键帧间隔**、**目标帧率**、**目标码率**。
  - **OSD 叠加**：日期时间/车牌/逻辑通道/经纬度/记录速度/卫星速度/连续驾驶时间等可按位叠加。
  - 是否启用音频输出。
- **通道列表**：物理通道 ↔ 逻辑通道 ↔ 通道类型（音视频/音频/视频）映射，是否连云台。
- **视频分析报警参数**：客车核载人数（超员报警）、疲劳程度阈值。
- **休眠唤醒模式**：条件唤醒（紧急报警/碰撞侧翻/开门触发）/ 定时唤醒（4 个时间段）/ 手动唤醒。

### 4.4 视频报警（概念）
- 视频报警**随位置信息汇报（0x0200）的附加信息一并上报**（扩展附加信息 ID）。
- 两类：
  - **视频相关报警**（信号丢失、信号遮挡等，按逻辑通道位标志）。
  - **异常驾驶行为**（疲劳 / 打电话 / 抽烟，疲劳程度 0–100 数值越大越严重）。
- 终端可上传**乘客流量**（视频分析上下车计数）。

### 4.5 实时音视频传输（核心机制）
- **实时音视频传输请求**：平台→终端；**终端发生特殊报警后，平台无须等待人工确认即主动下发**，启动实时传输。
- **传输控制**：切换主/子码流、暂停/恢复、关闭音视频通道、关闭双向对讲、仅关音频或仅关视频。
- **码流封装**：参考 RTP（RFC 3550），UDP 或 TCP 承载，负载补充"消息流水号 / SIM 卡号 / 逻辑通道号 / 数据类型（视频 I/P/B 帧、音频帧、透传）/ 分包标记 / 时间戳"等字段；帧头固定 `0x30 0x31 0x63 0x64`。
- **传输状态通知**：平台按间隔向终端回传通道**丢包率**。

### 4.6 历史音视频（查询/回放/下载，概念）
- **查询资源列表 → 终端上传资源列表**（过大走 808 分包，逐包应答）。
- **远程录像回放**：平台可控制 开始/暂停/结束/快进/关键帧快退/拖动/单帧上传；快进快退倍数 **1/2/4/8/16 倍**；回放方式含正常、快进、关键帧快退、关键帧播放、单帧。
- **文件上传指令**：终端经 **FTP** 把录像传到目标服务器；可设**任务执行条件**（bit0 WIFI / bit1 LAN / bit2 3G/4G 下可下载）；完成后通知平台。
- 上传控制：暂停 / 继续 / 取消。

### 4.7 云台控制（6 类，按逻辑通道）
旋转（0x9301）、调整焦距（0x9302）、调整光圈（0x9303）、雨刷（0x9304）、红外补光（0x9305）、变倍（0x9306）。

### 4.8 终端休眠唤醒
平台发**唤醒短信 `WAKEUPxx`**，`xx` = 唤醒时长（分钟，0–65536）；`0` = 一直唤醒直到 ACC ON 或低于额定电压。

## 五、音视频流服务器 ↔ 客户端播放软件

- **码流封装**：同 4.5 的 RTP 负载格式（流服务器↔客户端之间）。
- **URL 拉流**：政府监管平台向企业平台发预览/回放请求并成功后，拿到流服务器 IP/端口，由**客户端直接发 URL 向企业流服务器建链取流**，浏览器插件或专用软件播放。
- **URL 格式**（界面不显示）：
  `http://[服务器IP]:[端口]/[车牌号].[车牌颜色].[逻辑通道号].[音视频标志].[时效口令]`
  - 车牌号用 UTF-8 并按 RFC 2854 的 `application/x-www-form-urlencoded` 编码。
  - 时效口令 64 位 ASCII，每 24h 更新；归属地访问可空，**跨域访问须附车辆 5min 内任一时刻的卫星定位时间+经纬度**作位置验证（格式 `YYYYMMDD-HHMMSS-NXX.XXXXXX-EXXX.XXXXXX`）。

## 六、视频平台间通信（政府 ↔ 企业监管，概念）

- 基础与消息格式按 **JT/T 809—2011 第 4 章**；**复用已建立的定位平台间链路，不新增链路，无需身份验证**。
- **五大业务类流程**：
  1. 时效口令上报与请求
  2. 实时音视频
  3. 远程录像检索
  4. 远程录像下载
  5. 远程录像回放
- **时效口令机制（跨域监管核心）**：
  - 企业平台每日自动生成时效口令，主动上报**归属地政府平台**，归属地再向上级上报。
  - **跨域地区政府平台**需访问跨域车辆视频时，向上级政府平台请求当日**跨域时效口令**，上级按车辆当时地理位置应答。
  - 时效口令每 24h 更新；跨域访问必须在请求中带 `GNSS_DATA`（车辆入跨域后 5min 内任一点位）。
- **业务数据类型标识（主/从链路）**：时效口令 `0x1700/0x9700`、实时音视频 `0x1800/0x9800`、检索 `0x1900/0x9900`、回放 `0x1A00/0x9A00`、下载 `0x1B00/0x9B00`。
- **子业务类型**：主链路 `UP_*`（下级→上级）、从链路 `DOWN_*`（上级→下级）；如 `UP_REALVIDEO_MSG_STARTUP_ACK`、`DOWN_PLAYBACK_MSG_STARTUP` 等。
- **应答结果统一代码**：0 成功 / 1 失败 / 2 不支持 / 3 会话结束 / **4 时效口令错误** / **5 不满足跨域条件**。
- 下载完成通知含 **FTP 服务器 IP/端口/用户名/密码/路径**（由企业平台推给政府平台去取）。

## 七、视频报警类型编码（与川标/部省区分，重点）

**1078 表 38 视频报警类型编码（0x01xx 体系）：**
| 代码 | 名称 |
|---|---|
| 0x0101 | 视频信号丢失报警 |
| 0x0102 | 视频信号遮挡报警 |
| 0x0103 | 存储单元故障报警 |
| 0x0104 | 其他视频设备故障报警 |
| 0x0105 | 客车超员报警 |
| 0x0106 | 异常驾驶行为报警 |
| 0x0107 | 特殊报警录像达到存储阈值报警 |

⚠️ **编号空间区分（易混点）**：
- **1078 视频报警** = `0x01xx`（本标准，终端↔平台视频故障/行为类）。
- **地方主动安全补充规范的视频报警码** = `0x02xx`（视频补充协议，主防视频报警）。
- **部省交互规范智能监控报警** = `0xDxxx`（部级试行规范 B.1，主防/DSM/终端报警）。
- 三者都是"视频/主防相关报警"，但**编码体系与适用层级不同**：1078 是基础国标视频报警；0x02xx 是川标主防视频报警；0xDxxx 是部省主防报警。对接平台报警字典时须按来源分别映射，不要直接等同。

## 八、重点 / 易考点（概念速记）

1. **1078 = 视频通信协议**，建在 808（终端↔平台信令）+ 809（平台↔平台交换）之上；**1076 是视频终端技术要求，1078 是通信协议**，二者配套。
2. **三层架构**：终端↔平台、流服务器↔客户端、平台↔平台。
3. **信令走 808/809 链路，音视频码流走独立 RTP 链路**（UDP 或 TCP）；RTP 帧头固定 `0x30 0x31 0x63 0x64`。
4. **特殊报警后平台无须人工确认即主动下发实时视频**（5.5.1）——这是主动安全视频联动的关键。
5. **视频报警随 0x0200 位置汇报附加信息上报**；报警类型编码 `0x01xx`（与川标 0x02xx、部省 0xDxxx 不同体系，勿混）。
6. **时效口令**：64 位 ASCII、每 24h 更新；跨域访问验证核心，请求须带 GNSS_DATA（入跨域 5min 内点位）；URL 中界面不显示。
7. **云台控制 6 类**（0x9301~0x9306）；**休眠唤醒短信 `WAKEUPxx`**。
8. **远程回放倍数 1/2/4/8/16**，控制含单帧上传；**文件上传走 FTP**，带 WIFI/LAN/3G4G 任务执行条件。
9. **平台间复用 809 已建链路、不新增、无需身份验证**；应答结果 4=时效口令错误、5=不满足跨域条件。
10. **主/子码流**概念贯穿实时与历史（主码流高清、子码流低带宽预览）；OSD 可按位叠加日期/车牌/经纬度/速度等。
11. 编码支持：**视频 H.264(98)/H.265(99)/SVAC(101)/AVS(100)**；**音频 AAC(19)/G.711A(6)/G.711U(7)** 等（表 12）。
