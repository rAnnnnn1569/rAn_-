# JT/T 808 终端通信协议 学习笔记

> 记录 **车载终端 ↔ 监控平台** 的通信协议理解，**不转载标准原文**。
> 这一册重点：**报文长什么样、消息 ID 怎么分类、位置汇报为什么要看附加信息、盲区补报是什么**。

---

## 一、它解决什么问题

808 是车联网里**最底层、最高频**的一套协议：终端的注册、鉴权、心跳、位置、报警、多媒体、参数下发、区域/路线设置，全走它。

和相邻标准的关系：

| 标准 | 关系 |
|---|---|
| **794** | 规定终端"该有什么能力"，**不管报文**——能力最终靠 808 落地 |
| **1078** | 视频流走它自己的协议（RTP），但**信令（预览/回放/下载指令）复用 808 的消息体系** |
| **809** | 平台把 808 收来的数据**重新封装**后逐级上报给上级平台 |

**关键认知**：平台侧"能收到什么数据"，上限由 **794 的能力 + 808 的报文**共同决定。看到"平台没这个数据"，先分清是**终端没这个能力**、**终端有但没报**、还是**报了平台没解析**。

---

## 二、报文长什么样

```
7E │ 消息头(消息ID 2B + 消息体属性 2B + 终端手机号 6B + 流水号 2B) │ 消息体(可选) │ 校验码 1B │ 7E
```

| 项目 | 规定 |
|---|---|
| 头/尾标识 | `0x7E` |
| 字节序 | 大端 |
| 终端的唯一标识 | **终端手机号**（6 字节 BCD，即 SIM 卡号） |
| 校验码 | 从**消息头到消息体**逐字节**累加和**，取低 8 位（**注意：不是 CRC**） |
| 消息体属性 | 含消息体长度、是否分包、**加密方式**等标志位 |

**转义规则**（808 与 809 不同，别混）：

| 原始字节 | 转义为 |
|---|---|
| `0x7E` | `0x7D 0x02` |
| `0x7D` | `0x7D 0x01` |

**顺序有讲究**：发送时**先组包 → 计算校验 → 最后转义**；接收时**先还原转义 → 再验校验 → 最后解析**。搞反就会"校验总是失败"。

> **抓包第一直觉**：定界符判断协议——`7E` 是 808，`5B/5D` 是 809。看到 `7D 02` 要知道那是**数据里的 `0x7E`**，不是定界符。

## 三、消息 ID 的编号规律（记住规律比背表管用）

808 的消息 ID 是 **2 字节**，按**高位方向**分类，这是最省力的记法：

| 区间 | 方向 | 典型 |
|---|---|---|
| `0x01xx` | **终端 → 平台**（应答/上报/请求） | `0x0100` 注册、`0x0102` 鉴权、`0x0200` 位置汇报 |
| `0x8xxx` | **平台 → 终端**（下发/命令） | `0x8001` 平台通用应答、`0x8103` 设置参数、`0x8201` 位置查询 |
| `0x0001 / 0x8001` | **双向通用应答**（所有需应答消息的确认） | 收到就要回，超时未回则重传 |
| `0x8F00~0xFFFF` / `0x0F00~` 等 | **厂商自定义**预留段 | 地方/厂家扩展落在这些区间 |

**成对记忆**：`0x0100` 注册 ↔ `0x8100` 注册应答；`0x0102` 鉴权 ↔ `0x8001` 通用应答；`0x0200` 位置汇报 ↔ `0x8001`。**请求与应答成对**是这套协议的骨架。

**终端接入三步**（顺序固定）：

```
① 终端注册 0x0100 → 平台回 0x8100（给鉴权码）
② 终端鉴权 0x0102（带鉴权码）→ 平台回 0x8001
③ 终端心跳 0x0002 → 平台回 0x8001
```

> **排查含义**："终端一直上不了线"先看这三步卡在哪一步——卡注册多半是注册信息（终端型号/车牌/颜色/厂商 ID）与平台预置不符；卡鉴权多半是**鉴权码不匹配**（常见于从别的平台迁过来的设备）。

## 四、位置汇报（`0x0200`）：最核心的一条消息

`0x0200` 是平台数据量的绝对主力，由两部分组成：

```
位置基本信息（报警标志 4B + 状态 4B + 纬度 + 经度 + 高程 + 速度 + 方向 + 时间）
＋ 位置附加信息项列表（可选，按 ID + 长度 + 内容 排列）
```

- **报警标志**与**状态位**是位域：哪些报警在报、车辆是否 ACC 开、是否已定位、是否载客……都从这里"抠位"读出来。
- **附加信息项**是**按需出现**的（由"消息体属性"里的长度字段确定到底有几项）——这就是为什么**同一辆车不同时刻抓到的 `0x0200` 长度不一样**，属于正常现象，不是报文损坏。

常见附加信息项（ID 体系里挑常用的）：

| 附加信息 ID | 内容 |
|---|---|
| `0x01` | 里程 |
| `0x02` | 油量 |
| `0x03` | 行驶记录功能获取的速度 |
| `0x04` | 需要人工确认的报警事件 ID |
| `0x05` | 轮胎 / 胎压 |
| `0x25` | 扩展车辆信号状态位 |
| `0x2A` | IO 状态位（车门、各类开关量） |
| `0x30` | 无线通信网络信号强度 |
| `0x31` | GNSS 定位卫星数 |
| 地方扩展（如 `0x83~0x89`） | 主动安全类报警附加信息（碰撞、风险驾驶、疲劳、接打电话、抽烟、未检测到驾驶员等，随地方规范扩展） |

**运维含义**：解析"位置漂移""速度异常"这类争议，结论往往不来自主字段，而来自**附加信息里的卫星数、信号强度、IO 状态**——**"0 颗星时的高速度"与"正常定位下的高速度"是完全不同的两件事**。

## 五、批量上传与"盲区补报"（`0x0704`）

`0x0704` 是**一次上报多条定位数据**的消息，其中有个字段直接说明本批数据的性质：

- **正常位置批量汇报**：网络正常时的攒批上报；
- **盲区补报**：**终端侧缓存**的、在信号盲区期间没发出去的位置数据，回到网络后补报。

**运维含义**：**"盲区补报"是终端侧的行为，不是平台侧丢数据**。当"某车时段数据不全"时，先分清是：
1. 终端缓存了、后来补报（看 `0x0704` 的补报标志）；
2. 平台侧链路断了、恢复后按 809 补传（看 809 序列号与补传请求）；
3. 数据**真的丢了**。

三者在不同协议层，**混在一起谈就会互相甩锅**。地方规范通常会对缓存条数提要求（如缓存不少于若干千条定位信息）。

## 六、其他常打交道的消息

| 主题 | 消息 | 内容 |
|---|---|---|
| 参数 | 查询 `0x8104` / 查询应答 `0x0104` / 设置 `0x8103` | 参数按 **参数 ID** 组织：心跳间隔、TCP 应答超时、重传次数、各服务器地址端口、汇报策略（定时/定距）等 |
| 终端控制 | `0x8105` | 含**连接控制**：切换/切回指定服务器（做平台迁移、灾备切换会用到） |
| 区域/路线 | `0x8600~0x8607` 设置/删除圆·矩·多边形区域与路线；`0x8608` 查询 | 区域属性可配"进出是否报警给驾驶员/平台""超速阈值与持续时间""按时间段生效" |
| 地址设置 | 各服务器 IP/端口、APN、拨号账号，以及 IC 卡认证服务器 | 平台地址**下发到终端**才生效——迁移割接的关键动作 |
| 行驶记录 | `0x8700` 采集命令 / `0x0700` 上传；`0x8701` 参数下传 | 与 GB/T 19056 行驶记录仪对接 |
| 驾驶员身份 | 请求 `0x8702` / 上报 `0x0702` | 从业资格证 IC 卡插拔触发，含读卡结果与驾驶员信息 |
| 多媒体 | 事件 `0x0800` / 数据上传 `0x0801` / 上传应答 `0x8800`；拍摄 `0x8801` / 应答 `0x0805`；检索 `0x8802` / 应答 `0x0802`；上传命令 `0x8803` | 图片/音频/视频的组织、分包与**重传包请求** |
| 透传 | 下行 `0x8900` / 上行 `0x0900` | 承载非标业务，含 IC 卡认证透传（有超时，超时不重发） |
| 安全 | 平台 RSA 公钥 `0x8A00` / 终端 RSA 公钥 `0x0A00` | 公钥交换，为加密上报做基础 |

**拍摄参数里的分辨率取值**是排查"视频调取模糊"的常见抓手——分辨率是**档位编码**（取最接近值），不是任意值，终端不支持时会**取最接近的分辨率**拍摄。

## 七、常见故障 → 协议层判据速查

| 现象 | 先查什么 |
|---|---|
| 终端不上线 | 注册/鉴权三步卡在哪：注册信息是否相符、**鉴权码**是否一致 |
| 抓包校验总是失败 | 转义与校验的**处理顺序**（发送：组包→校验→转义；接收：还原→校验） |
| 同一车 `0x0200` 长度不一样 | 正常——**附加信息项是按需出现的**，由消息体属性长度字段决定 |
| 位置漂移 / 速度异常 | 看附加信息里的**卫星数、信号强度**，再判断是否终端侧问题 |
| 某时段数据不全 | 分清**终端盲区补报（`0x0704`）** vs **平台侧 809 补传** vs 真丢 |
| 迁移后终端连不上新平台 | 服务器地址是否**已下发到终端**（平台地址下发才生效） |
