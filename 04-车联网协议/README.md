# 车联网 / 道路运输车辆卫星定位协议 学习笔记

> 这里记录 JT/T 系列标准的**概念体系与要点归纳**（不转载标准原文）。
> 理解路径建议：**先分清"谁管什么"，再钻具体报文**。这一页是总览，具体见各分册。

## 一、先建立骨架：这些标准分别管什么

初学者最容易乱的地方，是把"设备标准"和"通信协议"混在一起。其实它们是**分层**的：

```
                    ┌─────────────────────────────────────┐
                    │  平台层（服务器侧该有什么能力）        │
                    │  JT/T 796 / GB/T 35658               │
                    └─────────────────────────────────────┘
                                    ↕
   ┌──────────────────────┐   ┌──────────────────────────┐
   │ 设备层（终端该有什么） │   │ 通信层（报文怎么传）        │
   │ JT/T 794  终端技术要求 │   │ JT/T 808  终端 ↔ 平台      │
   │ GB/T 19056 行驶记录仪  │   │ JT/T 809  平台 ↔ 平台      │
   └──────────────────────┘   └──────────────────────────┘
                                    ↕
                    ┌─────────────────────────────────────┐
                    │  视频系列（终端视频能力 + 视频传输）    │
                    │  JT/T 1076 视频终端技术要求           │
                    │  JT/T 1077 视频平台                  │
                    │  JT/T 1078 视频通信协议              │
                    │  编码：JT/T 415（车牌颜色等）         │
                    └─────────────────────────────────────┘
```

**一句话记住**：

| 标准 | 管什么 | 类比 |
|---|---|---|
| **794** | 终端**该有什么能力**（设备标准） | 手机该有什么硬件 |
| **808** | 终端与平台之间**怎么通信** | 手机怎么打电话 |
| **809** | 平台与平台之间**怎么交换** | 两个运营商之间怎么互通 |
| **1076** | 视频终端**该有什么能力** | 摄像头该有什么规格 |
| **1078** | 视频**怎么传** | 视频流的传输规则 |
| **796 / 35658** | 平台**该有什么能力** | 服务器该做什么 |

> **关键认知**：794 / 1076 只规定"能力"，**不规定报文**；所有报文最终靠 808 / 809 落地。所以"终端支持某功能"和"平台能收到某数据"之间的桥，就是 808 / 809。

## 二、808 与 809 的分工与定界符

| 项目 | JT/T 808 | JT/T 809 |
|---|---|---|
| 方向 | 终端 ↔ 平台 | 平台 ↔ 平台（上下级） |
| 定界符 | `0x7E` | `0x5B` / `0x5D` |
| 典型消息 ID | `0x0200` 位置汇报、`0x0102` 心跳、`0x8103` 参数设置 | `0x1700/0x9700` 等业务类型（上行 `UP_*` / 下行 `DOWN_*`） |
| 链路角色 | 终端登录、注册、鉴权 | 主链路 / 从链路（上级与下级方向不同） |

**两个高频概念**：

- **主链路 / 从链路**：809 里上级与下级之间是两条方向不同的链路，消息类型成对出现（`UP_xxx` 与 `DOWN_xxx`）。排查"上级收不到数据"时，要先确认是哪条链路、方向对不对。
- **定界符差异**：808 用 `0x7E`，809 用 `0x5B`/`0x5D`。抓包时**先看定界符判断是哪套协议**，是很实用的第一直觉。

**转义规则**（808 典型）：报文体中的 `0x7E` 需要转义（`0x7D 0x02`），`0x7D` 本身也要转义（`0x7D 0x01`）。抓包看到 `7D 02` 要知道它是数据而不是定界符。

## 三、报警码的"编号空间"必须区分（最大的坑）

同样是"报警"，不同来源的编码体系**完全不是一套**。直接把一个体系的码套到另一个体系上，是平台对接时最容易犯的错：

| 来源 | 编码形态 | 说明 |
|---|---|---|
| **1078 视频报警** | `0x01xx` | 基础视频报警（信号丢失、遮挡、存储器故障、异常驾驶行为等） |
| **地方补充规范（视频）** | `0x02xx` | 地方性主动安全视频报警 |
| **部级智能监控报警** | `0xDxxx` | 主动安全 / DSM 类报警的五位编码体系 |

**核心结论**：三者都叫"视频/主动安全报警"，但**编码体系与适用层级不同**，对接平台报警字典时**必须按来源分别映射，不要直接等同**。

**排查含义**：当"报警数量对不上"时，先确认双方说的是不是**同一个编号空间**的同一类报警，再谈数量差异——很多"数据丢了"的怀疑，最后都是"口径/体系不同"。

> 相关方法论见 [`../05-故障复盘/服务重启无效类故障排查方法论.md`](../05-故障复盘/服务重启无效类故障排查方法论.md) 第四节「数据对不上，先别怀疑链路」。

## 四、几个跨标准的"通用语言"

### 4.1 逻辑通道号

视频排查里，"通道"是最常用的定位坐标。基础对应关系（来自视频终端技术要求）：

| 通道 | 监控区域 |
|---|---|
| 1 | 驾驶员（**主动安全 / DSM 摄像头的常用位置**） |
| 2 | 车辆正前方（**不应具备补光功能**） |
| 3 | 车前门 |
| 4 | 车厢前部 |
| 5 | 车厢后部 |
| 7 | 行李舱 |
| 8 / 9 | 车辆左侧 / 右侧 |
| 10 | 车辆正后方 |
| 33 | 音频（驾驶员） |

**用法**：排查"某路没画面"时，先用通道号对齐"摄像头 → 平台报警字典 → 视频调取"三处的编号，再往下查链路。**通道号是三处对齐的通用语言**，编号对不上，后面全白查。

### 4.2 分辨率与验收硬指标（视频终端）

- 录像最低 **704×576（D1）**，且**其中一路应 ≥ 1280×720**（720P）；水平分辨力 ≥ 400 TVL。
- 录像总资源 **≥ 150h**，通道 2 帧率 ≥ 25fps，其余 ≥ 15fps。
- 特殊报警录像要从**报警发生前至少 1 分钟**开始打标记（事后取证的时间窗依据）。

### 4.3 疲劳 / 驾驶时间口径（终端侧默认值）

| 指标 | 默认值 |
|---|---|
| 单次连续驾驶 | 4 小时 |
| 单日累计驾驶 | 8 小时 |
| 有效停车休息 | 车辆静止且持续 ≥ 20 分钟 |
| 行驶开始 | 速度 > 0 且持续 ≥ 10 秒 |
| 禁行时段（默认） | 凌晨 2:00 – 5:00 |

> **跨设备/跨平台的"数据对不上"，很大比例来自这些阈值口径不同**（平台侧配置 vs 终端侧默认 vs 上级平台口径）。核对时要把三处阈值都拉出来比。

## 六、学习顺序建议

1. **先建立分层认知**（本页第一节）——知道哪个标准管哪一层，比背报文重要得多；
2. **再读 794**——搞清终端有什么能力，后面看报警/警示就知道"这个能力从哪来"；
3. **然后 808**（[JT808-终端通信协议.md](JT808-终端通信协议.md)）——理解"终端怎么把数据送到平台"，重点掌握消息 ID 体系与位置汇报附加信息；
4. **再 809**（[JT809-平台数据交换.md](JT809-平台数据交换.md)）——平台间交换，主从链路、序列号续编与补传对账；
5. **最后 1076 + 1078**——视频相对独立，但概念上仍复用 808/809 的信令链路。

> **一个实用技巧**：读到"某报警随位置汇报附加信息上报"这类话时，回到 808 找 `0x0200` 的附加信息 ID 表，两边对着看，理解会深一层。标准之间是**互引**的，别孤立地读。
