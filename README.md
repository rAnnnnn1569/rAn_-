## 技术方向与能力地图

**操作系统与硬件**

- Linux：CentOS 7 / Rocky Linux 9 系统管理、systemd 服务管理、日志分析、网络排障、SELinux、yum/dnf 源管理
- Windows Server：服务管理（`sc.exe` / `Get-CimInstance`）、事件日志（7000 / 7009 / 1053）、任务计划、NSSM 服务封装、`netsh` 端口转发
- 服务器硬件：Dell PowerEdge、PERC H330 RAID 配置与故障恢复、`ipmitool` BMC 硬件日志取证、`smartctl` / `dmesg` 磁盘坏道分析

**网络**

- iptables：DNAT / SNAT / MASQUERADE、多链路端口转发、规则幂等化改造
- 抓包分析：`tcpdump` / Wireshark / `tshark`，GRE 隧道链路抓包与 NAT 转发验证
- 排障方法论：按「进程 → 端口 → 本机防火墙 → 云安全组 → 路由」分层定位
- SMB 跨机连通排障：按「链路 → 云安全组 → 主机防火墙 → 共享名 → 共享权限∩NTFS 权限」五层定位；用 TCP 错误类型（`TimedOut` / `ConnectionRefused`）和防火墙丢包日志区分"包没到"与"包到了被丢"

**数据库**

- MySQL：一致性快照备份（`--single-transaction`）、binlog 增量归档与时间点恢复（PITR）、表分区、权限管理
- MongoDB：三节点副本集（PSS）、keyFile 认证、oplog 与内存参数调优、主从切换演练

**监控与告警**

- Zabbix 4.4 / 6.0：模板与宏、触发器表达式与函数、自动发现（LLD）、主动/被动模式、历史数据容量管理
- 告警通道：邮件 / 飞书机器人（交互式卡片）/ 语音电话三级分流
- Grafana 可视化、Zabbix API 自动化

**自动化与开发**

- Shell：幂等脚本、并发锁、空间护栏、断点续传、失败清理
- Python 3：`paramiko`（批量 SSH）、`requests`（API 对接与告警）、`pymongo` / `PyMySQL`
- 定时任务：Linux `cron` / Windows 任务计划程序

**容器**

- Docker / docker-compose：`network_mode: host`、日志限额、时区挂载、卷挂载、重启策略
- Nginx：反向代理、动静分离、systemd 服务化、按域名防盗链

**配置与脚本工程**

- 生产配置入库：只脱敏**服务器 IP** 与**口令/Token**，域名、平台名、容器名、部署路径等保留原样——配置的可读性正来自这些具体名字
- 脱敏不破坏逻辑：保留判定逻辑依赖的片段（如按 IP 第二段 dispatch 抓包网卡）、保留 DNAT 配对与端口语义
- 参考件形态入库：真实配置进公开仓前，先做"原值→新值"稳定性映射，再逐字节复核与敏感项零残留扫描

## 阅读约定

1. **概念优先**：先讲"这东西解决什么问题、在整体里处于哪一层"，再给命令。
2. **命令可复现**：给出的命令都在真实环境跑通过；未实测的会显式标注。
3. **踩坑有出处**：记录的是真实踩过的坑（含报错原文与根因），不是道听途说的"注意事项"。
4. **脱敏底线**：真实 IP 与口令不出现；域名、平台名等业务标识保留原样。
