# JT/T 808 报文组帧 / 消息体解析

## ⚖️ 铁律

1. **先按「结构自洽」确认消息ID，再补头**，别猜。判据见下节。
2. **补头的两个字段（终端手机号、流水号）报文里没有** → **必须向用户索要**，别拿示例值当结果交付。
3. **校验码算在「未转义」的字节上**：XOR 覆盖「消息ID → 消息体末尾」，转义在算完校验码之后做。
4. 结论分三级标注：**原文证实 / 实测证实 / 推断**。
5. 脚本输出必须**自带自检**（反转义重算校验码、XOR 全体应为 0），否则不许交付。

## 帧结构

```
7E │ 消息头 12B 或 17B │ 消息体 nB │ 校验码 1B │ 7E
```

🔴 **消息头有两套，先认头再动别的**（2026-09-30 实测证实，见下）：

**A. 国标 JT/T 808-2011~2019 第6章**（江苏苏标 DB32/T 3610.3 沿用）＝ **12 字节**（无分包时）：

| 字段 | 字节 | 说明 |
|---|---|---|
| 消息ID | 2 | 大端 |
| 消息体属性 | 2 | `长度(bit0-9) \| 加密方式(bit10-12) \| 分包(bit13)` |
| 终端手机号 | 6 | **BCD[6] = 12 位数字**；11 位手机号**左补 0** |
| 消息流水号 | 2 | 大端，上行按终端累加 |

**B. 川标 T/SCSDX 0003.3—2025 表2** ＝ **17 字节**（无分包时）—— 比国标多 5 字节：

| 字段 | 字节 | 说明 |
|---|---|---|
| 消息ID | 2 | 同上 |
| 消息体属性 | 2 | 同上 |
| **协议版本号** | **1** | 表2：默认 `0x51`（实测现网也有 `0x01`） |
| 终端手机号 | 10 | **BCD[10] = 20 位**（ICCID 式长卡号） |
| 消息流水号 | 2 | 同上 |

**判别式（确定性，不靠猜）**：`len(帧) == 头长 + 封装项 + 消息体长度`
（封装项 = 分包时 4B：消息包总数 2 + 包序号 2）。
唯一解即定案；两解并存时按「28B 基本信息里的定位时间是否为合法 BCD[6]」择优。
**实测**：143B 四川帧只满足 12B 头；70B 广西帧只满足 17B 头。
⚠️ **拿错头长会把消息体整体错位 5 字节**：广西帧按 12B 解 → 纬度 0.003°、时间 2058 年（垃圾值），
这正是「结构自洽法」第二次派上用场的地方 —— **先看纬经度/时间是否合法，再决定头长**。

其余规则（JT/T 808-2019）：

- **校验码**：从「消息ID」到「消息体末尾」全部字节**逐字节异或**，取低 8 位。
- **转义**：`0x7E → 0x7D 0x02`、`0x7D → 0x7D 0x01`，作用范围 = **消息头+消息体+校验码**（首尾 7E 不转义）。
- 全大端。

## 判定「这段 hex 是哪个消息的消息体」

用**结构自洽法**（本次实测有效，比猜可靠）：

1. 先试**0x0200 位置信息汇报**：定长部分 **28 字节** =
   `报警标志DWORD + 状态DWORD + 纬度DWORD + 经度DWORD + 高程WORD + 速度WORD + 方向WORD + 时间BCD[6]`
2. 从第 29 字节起按 `ID(1) + 长度(1) + 值(n)` 走 TLV，**看链尾是否恰好落在消息体最后一个字节**。
3. 三条同时成立即可定案：
   - 时间字段解出来是**合法日期**（如 `260921164544` → 2026-09-21 16:45:44）；
   - 纬度 ≤ 90、经度 ≤ 180（换算 = 值 / 10^6）；
   - **TLV 链恰好对齐末尾**（多一字节或少一字节都不算）。
4. 消息体属性里的**长度位**应等于实际消息体字节数 —— 又一个交叉验证点。

> 反例排除：若把 28 字节定长往前/后错一位，纬度会 > 90（非法），立刻暴露。

## 标准归属判定（少走弯路）

- **0x14/0x15/0x16/0x17 不是 JT/T 808-2019 原表内容**，是**川标 T/SCSDX 0003.3 表48 / 四川新主防视频补充协议表13** 的扩展（苏标 DB32/T 3610.3 表16 只扩了 `0x64`）。
- 所以：一条含 `0x14~0x17` 的 0x0200 报文，特征偏**川标/四川口径**；含 `0x64` 不带 `0x14~0x17` 的，偏**苏标口径**。

## 坑（踩过的）

1. **`lstrip("0x")` 会吃掉前导 0** —— `"0200".lstrip("0x")` = `"200"`，用 `int(s, 16)` 直接转。
2. **校验码别算在转义后的字节上** —— `xor(frame[1:-1])` 是错的（含 7D 01/7D 02 填充）。必须 `xor(消息头+消息体)`。
3. **SIM 是 12 位 BCD**：给 11 位手机号要**左补 0**（`13800138000` → `013800138000`），补错位整条报文终端不认。
4. **附加信息里出现 0 值不等于"没有"** —— 要看该 ID 是否本车启用（如 `0x02 油量=0`、`0x03 行驶记录速度=0` 多为"未使用"，不是"油量真的是 0"）。
5. **`0x2B 模拟量` 的物理含义随终端 AD 标定变**，脚本只给 `AD0/AD1` 原始值，**别说成"温度/电压"**（无标定表就是未证实）。
6. **`--parse` 只覆盖 0x0200**；别的消息 ID 结构不同，别硬套 28 字节。
