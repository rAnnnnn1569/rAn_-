# docx 段落级批量格式改写（OOXML 直改）

## ⚖️ 铁律

1. **只改 `word/document.xml` 一个 zip 条目**，其余条目必须逐字节不变 —— 这是可验证的，必须验。
2. **零附带损伤的硬指标：差异段落实体数 == 计划变更数**。数字对不上就是有漏改或多改，不许放过。
3. **段落正则必须「自闭合优先」**，否则 `<w:p .../>` 会贪婪吞到下一段，生成非法 XML：
   ```python
   P_RE = re.compile(r"<w:p\b[^>]*/>|<w:p\b[^>]*>.*?</w:p>", re.S)
   ```
   改完必检：`ET.fromstring` 通过 **且** 游离 `w:pPr` 计数为 0。
4. **`w:pPr` 子元素须遵 schema 顺序**：`pStyle → spacing → ind → jc → outlineLvl → rPr`。顺序错 Word 会报「内容有问题」。
5. **目标集用 `w14:paraId` 清单**（跨轮次稳定）。不要用序号、标题文字做匹配键 —— 改过一轮后文字就变了。
6. **格式模板从参照段程序化提取，绝不手抄**。
7. **改动前先备份到原目录**，写回后回读 sha 校验。
8. **文字严禁改动**（除明确要求「补序号」这类）；验证手段：全文 `w:t` 拼接必须逐字符一致。

## 何时用／边界

| 场景 | 用本 skill |
|---|---|
| 把 N 个标题的格式改成某参照段的格式 | ✅ |
| 只改格式、内容一字不动 | ✅ |
| 两份文档全文对照找差异 | ❌ 用 `docx-fulltext-diff` |
| 改封面/页眉/页码等 sectPr 级设置 | ⚠️ 超出范围，需另议 |

## 快速上手

```bash
PY="C:/Users/Administrator/.workbuddy/binaries/python/versions/3.13.12/python.exe"
S="C:/Users/Administrator/.workbuddy/skills/docx-batch-reformat/scripts/docx_reformat.py"

# 1) 看参照段格式指纹
"$PY" "$S" ref  "D:/x/主文档.docx" 2FBA55EF

# 2) 列/筛段落，导出目标 pid 清单
"$PY" "$S" list "D:/x/主文档.docx" --pstyle 8 --pidfile pids.txt
"$PY" "$S" list "D:/x/主文档.docx" --grep "说明" --pidfile notes.txt

# 3) 按参照段格式批量改写（只改格式，文字不动；outlineLvl 沿用）
"$PY" "$S" apply "D:/x/主文档.docx" 2FBA55EF --pids pids.txt --out new.docx

# 4) 零附带损伤校验（退出码非 0 即失败）
"$PY" "$S" verify "D:/x/主文档.docx" new.docx --pids pids.txt

# 5) 备份 + 写回（被锁定会自动重试 3 次）
"$PY" "$S" deploy "D:/x/主文档.docx" new.docx
```

> `apply` 默认**沿用每段的 `w:outlineLvl`**；要让所有目标段都用参照段的大纲级别，加 `--no-outline`。

## 关键概念

| 项 | 说明 |
|---|---|
| `w14:paraId` | 段落唯一 ID，稳定的定位键 |
| `w:outlineLvl` | 大纲级别，**0 起算**：val=0→一级、1→二级、2→三级…；人话级别 = val+1 |
| `w:pStyle` | 具名段落样式引用（如 `8`=Body Text）。**优先用样式引用，不要手抄直接格式** |
| `w:ind w:firstLine="640"` | 首行缩进 640 twips（第 2 参数 `firstLineChars="200"` = 2 字符） |
| 序号 | 标题文字常**不含**序号，序号由 `numbering.xml` 渲染；要写死序号须自己复算并逐条兜对 |

## 本项目已知体例（`中卫北斗云信息服务平台备案资料`）

- ⚠️ 文件名含「- 副本 - 副本」，路径在《川交函（2026）275号…》目录下。
- **样式 `styleId=8` 的英文名是 `Body Text`，中文 Word 显示名是「正文文本」，仿宋 + sz=31（15.5 磅）**。文档里凡说「正文文本格式」指的就是它。
  - 🔴 查具名样式要**按 styleId 与英文 `w:name` 双路检索**，只搜中文显示名会漏（我漏过一次）。
- 体例：小标题（「一、服务方式」等）用**直接格式**（黑体 sz31 + ind 640 + outlineLvl）；**正文段一律 `pStyle=8`**。
- 「说明：」段共 127 处，全在**单列表格单元格内**（虚线边框，`tblW=8302 dxa`），结构为「警示图标 drawing run + 文字 run」，原为加粗。表格行高全部 `hRule="atLeast"`，故加段前距不会截断。
- 手册章节（第三章「"中卫北斗云信息服务平台"操作手册」）= 标题序列 idx 25–472（448 个，seq25 为章标题）。章标题 paraId `5FB5C0FB`，**二级、不可动**。

## 踩坑清单

1. **WPS 独占锁**：只要 WPS 打开了该 docx，Python 就以独占方式打不开（`PermissionError WinError 32 / Errno 13`），**与 editor_sdk 是否打开无关**。
   - 判据：目录内有无对应 `~$` 锁文件 + `open(p,"r+b")` 试写。
   - 处置：`deploy` 子命令已内置「重试 3 次、间隔 4 秒」；仍失败就投放备用文件名，请用户关 WPS。
   - ⚠️ **写回后若 WPS 仍开着该文件，用户在 WPS 里点保存会把内存旧版覆盖回来** —— 务必提醒「先关闭不保存，再重新打开」。
2. **`shutil.copy2` 保留源 mtime** → 写回后 docx 的 mtime 显示为**产物生成时刻**，不要误判成「用户又改过」。
3. **WPS 重存会搅动书签顺序**：正文文字可能零差异，但 `<w:bookmarkStart>` 顺序会调换几十处。判定「有没有实质变化」要**按段落对齐后再逐项比对属性**，别直接逐字符 diff（2MB 会超时）。
4. **别把「孤例格式」直接当成误操作**。先全文检索同款格式指纹 —— 它很可能是**既有体例**的成员，是有人在向体例对齐。这个误判我犯过一次。
5. **本机环境**：Bash 的 PATH 残缺（`head`/`grep`/`dirname`/`cat` 均 not found），命令输出**必须重定向到文件再用 Read 读**；PowerShell 工具不可用。固定套路：**Write 脚本 → 绝对路径 python 执行 → Read 结果文件**。
6. **`tasklist` 输出是 GBK**，Python `subprocess` 直接按 UTF-8 解会抛 `UnicodeDecodeError`，要指定 `encoding="gbk"` 或兜底 `latin-1`。
7. `editor_sdk` 的 `doc_modify_paragraph` 的 `heading_lvl` 参数写的是 **`w:pStyle`（标题样式）**，不是直接大纲级别 → 做不了「正文外观 + N 级大纲」的组合，必须直改 XML。
8. **「标题」与「正文」的干净判据是 `w:outlineLvl`**：标题段必带 `w:outlineLvl`，正文段不带。
   要把「某一章的全部正文」捞出来时，用四个条件**相交**，比按文字/序号匹配可靠得多：
   ① 落在该章 idx 区间内（从章标题起，到下一个 `outlineLvl<=1` 的标题为止）
   ② **不含** `<w:outlineLvl`
   ③ 有实际文字（`w:t` 非空）
   ④ 不在「已完成清单」里（避免二次加工已改过的段）
   本项目实测：手册章节 2023 段 → 捞出 **966 段正文**（表格内 495 + 独立 471），另跳过 574 已改段、460 无文字段、21 自闭合空段、2 个标题。
9. **🔴 「正文」的边界必须先分类计数、抽样看清，再动手**。改「标题」和改「正文」是两件事 —— 只改了标题，用户会回来说「正文的格式没有变啊」（本项目真实发生）。
   正文往往横跨「独立段落」与「**表格单元格内段落**」（截图旁的标注文字就在单元格里），还夹着加粗段、居中段。
   动手前先跑 `list` 分类计数 + 抽样打印内容，确认三件事：**含不含表格内？含不含加粗？含不含居中/注记？**
   - 默认判断：用户说「整章统一为正文格式」时，**表格内说明文字也应一起改**（否则截图旁标注仍是小字，观感依旧不统一）。
   - 按「以正文文本格式显示」的口径，**加粗应一并去掉**（参照段无加粗）——这与用户要求「说明」去加粗是同一逻辑。
