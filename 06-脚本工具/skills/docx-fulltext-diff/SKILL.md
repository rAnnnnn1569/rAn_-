# docx 全文严格对照（两份文档 diff）

## 适用场景

- 用户给两份 .docx（旧版/新版、甲乙方版本、归档版/在改版），要求"严格对照不同点""全文通读"。
- 需要判断：结构改动、新增章节、**被删除的内容**、文字级改动、篇幅变化。
- 顺带必查：**文件名标注的版本与封面/内页版本是否一致**（实测踩过：文件标 `_V8.docx` 实为最新版，标 `_V8.9.6_20260528.docx` 反而是旧版）。
- **场景 B：一个大文档里的某一章节 vs 一份独立文档**（实测：备案资料.docx 内嵌的"操作手册"章节 vs 独立操作手册.docx）。见下方「场景 B」。

## 铁律

1. **必须"全文通读"，不能只读 diff**。diff 只能定位，结论要回原文核对；用户说"严格对照"时更要把两份正文逐段读完。
2. **"A 有 B 无"必须逐条回原文 grep 复核**，避免把"章节重排导致的位置变化"误报成"删除"。
3. 判断新旧以 **`docProps/core.xml` 的 dcterms:modified + 封面内页日期** 为准，**不以文件名为准**。

## 执行步骤

### 1. 准备运行环境（重要，实测坑）

- 🔴 **本机固定套路（2026-09-23 复测：Bash 与 PowerShell 双双不可用，别再试 PowerShell）**：
  - Bash 的 PATH 整体失效（`ls`/`grep`/`mkdir`/`dirname: command not found`，shim 报 `cd: null directory`）→ **不要用 bash 做任何解析**（`cd` 也会失败，必须全用绝对路径）。
  - **PowerShell 工具同样不可用**（脚本 exit 1、无产物）→ 早期版本本文写的"改用 PowerShell"已作废。
  - ✅ **唯一可靠姿势**：Write 写 .py（路径**硬编码**在脚本内，`sys.path.insert` 引常量）→ Bash 用**绝对路径**调 python，stdout 重定向到 .txt → Read 读 .txt。
    ```bash
    "C:/Users/Administrator/.workbuddy/binaries/python/versions/3.13.12/python.exe" "H:/.../an.py" > "H:/.../an.txt" 2>&1 ; echo DONE
    ```
  - bash 的 `>` 重定向产物**可以被 Read 正常读取**；含中文的参数**不要经 shell 传递**。

### 2. 配置目标

在 skill 的 `scripts/` 下建 `targets.txt`（UTF-8）：
```
<A 文件绝对路径>
<B 文件绝对路径>
<输出目录，可省>
```

### 3. 运行

```powershell
& "C:\Users\Administrator\.workbuddy\binaries\python\versions\3.13.12\python.exe" "C:\Users\Administrator\.workbuddy\skills\docx-fulltext-diff\scripts\docx_diff.py"
```

产出（默认写到 `scripts/out/`）：

| 文件 | 内容 |
|---|---|
| `meta.txt` | 文件大小、部件数、媒体数量与总大小、页数/字数、core.xml 作者与创建/修改时间、表格数与图片引用数、**样式分布（含示例）** |
| `A_body.txt` / `B_body.txt` | 去 TOC 后的正文，逐段带序号、样式标签、图片计数 |
| `sentdiff.txt` | 句子级 diff：`[仅A]` / `[仅B]` / `[改写]` |
| `done.txt` | 段落数、字符数、差异计数汇总 |

### 4. 判读顺序

1. `meta.txt` → 定新旧、定篇幅；**核对文件名与内页版本**。
2. `A_body.txt` / `B_body.txt` 的**目录区**（TOC 段）→ 拿章节树，做一级/二级结构对照。
3. 两份**正文逐段通读**（Read 分批，每批 150~200 行）→ 记录新增/删除/改写。
4. `sentdiff.txt` → 定位疑似删除项，**再 grep 原文复核**。

## 场景 B：大文档内某一章节 vs 独立文档

实测案例：`中卫北斗云信息服务平台备案资料.docx`（89.9MB，整份备案材料）里的「三、"中卫北斗云信息服务平台"操作手册」章节，vs `四川省道路运输车辆企业监控平台操作手册_V8.9.6_20260918.docx`（84.8MB 独立手册）。

**做法（在标准流程上加 3 步）：**

1. **先跑一次标准 `docx_diff.py`**（A=大文档，B=独立文档）→ 得到 `A_with_toc.txt`（逐段带 `序号 [样式] {IMGxN} 文本`）。
2. **看大文档的样式分布**：大文档常常**整篇没有标题样式**（`meta.txt` 里 `(none)` 占绝大多数），此时 TOC 自动识别会失败（`A_body == A_full`），**不要慌，也不要去猜样式** —— 直接进 `A_with_toc.txt` 用章节标题文字定位边界（如 grep `操作手册`、`^三、`、`^四、`），拿到起止段落号。
3. **切片并单独 diff**：写一个小脚本 `load(path, lo, hi)` 从 `A_with_toc.txt` 按段落号区间取文本（剥掉 `[S..]`、`{IMGxN}` 前缀），再与 `B_body.txt` 做句子级 diff。
   产出必看两项：**段落/字符数比**（判断是精简版还是完整版）、**句子相似度**（判断同源程度）。

**关键判据（本次实测有效）：**

- **相似度 0.77 左右 + 互有增删 ⇒ 不是同一版本的两个副本，而是"同源分支"**：本次内嵌章节比 5-27 版独立手册多了章节编号、真实 URL、4.8 节，却少了事件分类/处警中心/部分报表，人脸识别还停在「川标2021」（5-27 版已是「川标2025」）⇒ 判定为**备案编制时的定制版，不是任何一个独立版本的原文**。

**2026-09-23 复核（同一对文件，精确定量为一版定论）：**

- 范围：A（备案资料）= 段落流 idx 563~2585（2023 段）；B（独立手册）= idx 481 起（**封面 0~18、目录 19~477 必须先切掉**，目录项样式 16/18/13/17 与正文标题样式 2/3/4/5 一一对应，共 457 条）。
- 非空文本段 **1541 vs 1562**，`SequenceMatcher` 判 **1533 段完全一致（99.5%）**，仅 15 个差异块：
  **23 段 B 独有 + 2 段 A 独有 + 6 段文字不同**。Counter 交叉验证 `+29 / −8` 完全吻合。
- 这 23 段集中在 **8 个缺失小节**：`修改密码`（车辆登录下）／`押运员信息`（表格内 1 段）／`主防报警参数设置（川标2025）`／`乘客超员报警参数设置`／`终端参数巡检任务`／`指令发送`→`指令下发`·`发送历史`／`录像月历定时下发`／`2天内超时驾驶情况`。
- 6 段文字不同里 **只有 2 段是真错**，其余 4 段是"有意替换"或漏标尾注：
  - 🔴 `人脸识别设置（川标2021）` → 应为 **2025**（标题自己写的就是「川标2025」），且漏了「、更新」（B 是"添加、更新功能"）。
  - 🔴 `历史视频` 整句重写（A 写"搜索栏查询/按通道时间报警类型检索"，B 写"右键→视频监控→历史视频"完整操作路径）。
  - ⚪ 2 段 URL：A 用真实地址 `http://iot.example.com:8800/`，B 用占位符 `http://服务器IP:端口号/` —— **属有意替换，不算错**；但 A 的 `/cgo8/` 小写 vs B 的 `/Cgo8/` 大写是个待确认项。
  - ⚪ 2 段漏尾注：A 少了「如下图：」「，如下图：」。
- 另 1 处**纯结构差异**：`地图工具` 在 B 是 heading 4，A 是正文段（无大纲级别、无序号）—— 见技术坑 12。
- **图片（用户说"除外"，但仍要统计）**：A 手册章 193 图 / B 正文 189 图；差额 = A 多 7 处内嵌图（6 处 `<w:drawing>` 带 rId + 1 处）+ B 独有段内 3 图（7−3=4）✓。
- **表格**：A 片内 127 张 / B 正文 129 张，差 2 张；表格内非空段 622 vs 628，差 6 段（正好等于 B 独有段中位于表格内的 6 段）✓。
- **带 `\d+(\.\d+)*\.?` 前缀的短行 = 编号标题**（大文档无样式时，这是唯一可靠的章节树来源）；独立文档则用 `pStyle` 层级（S2/S3/S4/S5）还原章节树。
- **版本演进看"版本后缀词"**：`（川标2021）`→`（川标2025）` 这类括号里的年份/标准号是判断新旧的硬证据。
- **URL 写法能判用途**：真实域名（`https://bd.example.com:8082/`）多见于备案/交付定稿；占位符（`http://服务器IP:端口号/`）多见于产品通用手册。

## 已实测的技术坑

1. 🔴 **段落文本正则必须写 `<w:t(?:\s[^>]*)?>(.*?)</w:t>`**。
   写成 `<w:t[^>]*>` 会**误匹配 `<w:tab .../>`、`<w:tbl>`** → 提取出的"段落"里混进大段 XML，段落数虚高数倍（实测 A 739/2026 皆为污染值），后续 diff 全废。
2. **先按 `</w:p>` 切段，再在段内取 `w:t`**，才能保证段落边界正确。
3. **TOC 段过滤**：TOC 用专门的 `pStyle`。**不要猜样式 ID** —— 先看 `meta.txt` 的样式分布：TOC 样式会与正文标题样式**数量一一对应**（实测 TOC 样式 13/16/17/18 的段数 324/61/63/9，与正文标题样式 4/3/5/2 完全相同），且 TOC 段文本末尾带页码（`…- 1 -` 或 `…1`）。
4. `app.xml` 的 `Pages` / `Words` / `Characters` 可做篇幅对照；`Words` 是 WPS 计数口径，与中文实际字数无关，**别当字数用**。
5. 媒体统计：`word/media/*` 的**数量 + 总字节**比页数更能反映内容扩充幅度。
6. 段落级 `difflib` 在结构大改时会产出巨量 `replace` 块；**句子级（按 `。！？；` 切）更易读**，且能识别"一对一句子改写"。
7. 图片来源三种写法都要数：`<a:blip` / `<w:drawing` / `<w:pict`。
8. **PowerShell 的 `*>` 重定向产物 Read 工具读不了**（报 `Cannot display content of binary file`）→ 想留日志就让 **Python 脚本内部 `open(...,'w',encoding='utf-8')` 写文件**；必须用 PowerShell 重定向时改 `| Out-File -Encoding utf8`。
9. 生成 xlsx 对照表需 **openpyxl**，managed python 里没有 → 跑之前设 `$env:PYTHONPATH="C:\Users\Administrator\.workbuddy\binaries\python\envs\pylibs"`。
10. 🔴 **比对前必须剥离标题序号前缀**：若一侧标题自带手工编号（`1.` / `1.1.1.`）而另一侧靠 Word 编号域渲染（**文字里根本没有序号**），直接比文本会**全部对不上**。统一 `re.sub(r'^(\d+\.)+\s*', '', s)` 后再比。
11. 🔴 **必须做"多重集合"交叉验证**：`SequenceMatcher` 是启发式的，可能把差异"藏"进 `equal` 块。用 `Counter(归一化文本)` 独立算一遍差集（`cb - ca` / `ca - cb`），**两侧必须自洽**才敢下结论。
    本次实测：序列 diff 给出 `23 insert + 6 replace + 2 delete`；Counter 给出 `仅B有 29 / 仅A有 8`；`29 = 23+6`、`8 = 2+6`，完全吻合 → 判定对齐无误。
12. 🔴 **"文字相同" ≠ "结构相同"**：同一句话可能在一侧是**标题**（带 `pStyle`/`outlineLvl`），在另一侧是**正文段**。纯文本 diff 会判为 equal，**只有比"标题集合"才暴露**。
    实测：`地图工具` 在独立手册里是 heading 4，在备案文档里是普通正文段（无大纲级别、无序号）。
    做法：另外输出「标题集合差集」——一侧按 `pStyle ∈ {2,3,4,5}`、另一侧按 `outlineLvl` 非空提取标题，**剥序号后**做集合差集。
13. **段落流要带"表格深度"标记**：用 `ET` 递归 `w:tbl → w:tr → w:tc` 时给 `depth+1`，才能区分"独立正文段"与"表格单元格内的说明/标注"——两者常被混为一谈，改动范围会差几百段（本次：独立正文 471 段 vs 表格内 495 段）。
14. **范围要"可证伪地"界定**：大文档切片时不能只靠标题文字 grep。同时统计"片内 `<w:tbl>` 数、非空文本段数、图片数"，切片后与独立文档对账（本次：127 表 vs 129 表、1541 段 vs 1562 段、193 图 vs 189 图），差额能被差异清单逐条解释才算切对了。

## 输出要求（给用户的答复）

- **结论先行**：先定性两份是什么关系（同版副本？旧版/新版？哪份新？），再列差异。
- 必含三张清单：**元信息对照表 / 章节结构对照 / A 有 B 无（真删除项）**。
- "A 有 B 无"要**标明核查方式**（grep 复核过），避免误报。
- 涉密/备案类文档**只给对照结果，不擅自另存新文件**；用户明确要落盘时再导出。
