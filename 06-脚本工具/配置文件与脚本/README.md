# 配置文件与运维脚本

> 从真实生产环境整理出来的 9 份配置与脚本。**脱敏范围仅限服务器 IP 与口令/Token**；
> 域名、平台名、地域名、容器名、DLL 名、部署路径、账号一律保留原样，便于对照真实环境阅读。

## 脱敏规则

只动两类东西，其余一律原样：

| 类别 | 处理方式 |
|---|---|
| **服务器 IP（公网）** | 稳定 1:1 映射到 RFC 5737 文档保留段 `192.0.2.0/24`，同 IP 全局一致 —— 保证 DNAT 配对与端口语义不变 |
| **服务器 IP（私网）** | 保留网络段位（`10.x` / `192.168.x` / `172.16.x`），仅替换主机位 —— `03` 的抓包网卡 dispatch 依赖 IP 第二段，段位不能动 |
| **数据库口令** | `DBPassword=` 生效行整段替换为 `CHANGE_ME` |
| **命令行默认口令** | `--pwd` 默认值替换为 `CHANGE_ME` |
| **机器人 Webhook Token** | UUID 替换为全 0 的 `00000000-0000-0000-0000-000000000000` |

**明确保留**：业务域名与对象存储地址、平台与上级机构名称、地域名、容器名与 DLL 名、宿主机部署目录、平台账号、车牌号。

## 五个值得单独看的设计

1. **`03` 用 IP 第二段反推抓包网卡** —— 多 GRE 隧道场景下，网卡名不能靠猜；靠地址段位反推是唯一可靠办法。脚本里 `expr $flag + 0` 做数值校验，解析不出就退出，而不是拿着空网卡名去跑 tcpdump。
2. **`04` 的幂等封装 + 端口变更检测** —— 直接 `iptables -A` 重复执行会堆规则；`-C` 查重解决"有没有"，但"端口改了"需要把旧规则的 dport 模糊化后再比对，这是两层问题。
3. **`05` 的签名算法** —— `MD5(MD5(pwd) + t)`，双重 MD5 是为了让时间戳参与运算、避免重放；`t` 取毫秒。
4. **`06` 用 docker secrets 而非 environment** —— `MYSQL_PASSWORD` 通过 `file: ./.MYSQL_PASSWORD` 挂载，密码不进 compose 文件、不进 `docker inspect` 明文。
5. **`08` 的两次采样比对** —— 监控接口的"有数据"不等于"链路通"，只有 `sendCnt` 在采样间隔内**增长**才说明真的在转发。

## 使用提醒

- 这几份是**配置与编排**，不是完整可跑项目：`.lake` 里只有片段，缺业务代码与数据。
- `04` 需 root 执行；`03` 需 `sudo tcpdump`；`09` 需管理员命令行。
- `02` / `06` 依赖宿主机目录已存在，否则容器会 `CrashLoopBackOff`（文件缺失 vs 目录缺失报错不同）。
- `08` 的两个检测地址与飞书 Webhook 已按上表脱敏，实跑前需替换为真实值。
